## Two modes
1. **Linked** (Warden desktop app installed on this computer): the extension talks to the app through native messaging. The extension only reports the front tab's site and acts on the app's commands (blocked page, close tab). The APP does all network calls (spend-tick with `site`), the pill and the countdown. The extension makes NO network calls in linked mode.
2. **Standalone** (no desktop app: Firefox on Android, or a computer without the app): the extension signs in and talks to the Warden API itself (same endpoints as the desktop app).
Mode pick: `runtime.connectNative(HOST)` succeeds and the host answers `hello` → linked. "host not found" error → standalone. Re-check on browser start and every 5 min while standalone (the user may install the app later).

## Native messaging protocol (JSON, browser's 4-byte length framing)
Host names (lowercase, dots only): staging `in.weenja.warden.staging`, prod `in.weenja.warden` later.
Extension ids: Firefox staging `extension-staging@getwarden.app`. Chrome: fixed id from a `key` (public key) in the staging manifest. The extension builder generates the RSA key pair, keeps the PRIVATE key outside the repo at `~/.config/warden/extension-staging-key.pem`, puts the public key in the manifest and writes the resulting id in `extension/README.md`. The desktop builder reads that id from `extension/README.md` (or uses the placeholder `EXTENSION_ID_CHROME_STAGING` in one constant until it appears).

Extension → app:
- `{"type":"hello","ext_version":"0.1.0"}` first message.
- `{"type":"tab","site":"m.youtube.com"|null,"idle":false}` on every change (active tab, URL host, focused window, idle). `site` = lowercase hostname of the active tab in the last focused browser window, `null` for non-http(s) pages. `idle` = screen locked, or no input for 5 min and the tab is not playing audio.
- `{"type":"show_app"}` user pressed "Open Warden" (app shows its sign-in window or popover).
App → extension:
- `{"type":"hello","app_version":"…"}` reply.
- `{"type":"state","signed_in":true,"points":42,"low":false,"locked":false,"guarded_sites":["youtube.com"],"draining":{"site":"youtube.com","per_min":1}|null,"device_name":"Sam's MacBook Air"}` on every change (and right after hello). `locked` = guarded sites are blocked (0 pts, token expired offline, or daily max).
- `{"type":"close_tab","site":"youtube.com"}` (pill Stop, or lock while on a guarded site if the extension has not already shown the blocked page).
Site match (both sides, one tested function each): a host is guarded when it equals a guarded site or ends with "." + it (`m.youtube.com` ⊂ `youtube.com`). The server decides the charge (`spend-tick {site}` → most specific guarded site, 404 when none).

## Extension builder (`extension/`, MV3 TypeScript)
- One codebase, build with esbuild (no framework): `npm run build` → `dist/chrome/` (service worker) and `dist/firefox/` (event page `background.scripts`, `browser_specific_settings.gecko` id + `gecko_android`). `npm run zip` → zips. Use `browser.*` via a thin shim or `chrome.*` with promises (both browsers support promise-style `chrome.*` in MV3; check current MDN + developer.chrome.com docs).
- Permissions (match the mockup list; add only what is needed and update the popup/first-run list to the exact manifest): `tabs`, `nativeMessaging`, `idle`, `alarms`, `storage`, `declarativeNetRequest`, `webRequest` (standalone sign-in, see below), `scripting` only if the chip needs it. Host permissions: only the staging Supabase origin. No `<all_urls>`. The in-page chip (standalone only) uses `optional_host_permissions` for the guarded sites, asked with a button in the popup (user gesture), then `scripting.registerContentScripts`.
- UI from the mockup: toolbar badge (points; coral 0/lock, amber low, grey not linked), popup states (draining, site not guarded, low, 0 pts, app signed out → "Open Warden", standalone sign-in, standalone signed in), "What it sends" panel, first-run tab (opens once), blocked page (`blocked.html?site=`: "that's your lot." / "Out of points. Earn more to use <site>." / Go back / Close tab), in-page chip (standalone). Light/dark from the OS.
- Blocking at 0: `declarativeNetRequest` dynamic `block` rule for `main_frame` + `requestDomains` = guarded sites while locked (no host permission needed for block), and `tabs.onUpdated` sends any tab on a guarded site to `blocked.html`. Remove rules when unlocked.
- Standalone sign-in: Apple hidden (disabled on staging). Email code flow built (works once SMTP exists). Google: the redirect allowlist has only `warden://auth-callback`, and Firefox Android has no `identity` API. So: open a tab at `/auth/v1/authorize?provider=google&redirect_to=warden://auth-callback&code_challenge=…&code_challenge_method=s256`; read the `Location` header of the Supabase `/auth/v1/callback` response with `webRequest.onHeadersReceived` (`responseHeaders`; Firefox can block/redirect the tab to an extension page, Chrome observes then closes the tab); take `code`; `POST /auth/v1/token?grant_type=pkce`. PKCE makes a seen code useless to others. Verify this really works in Chrome and Firefox; if Chrome fails, report and propose the cleanest fix (do not change Supabase settings).
- Google with no Warden account: port the desktop rule from `desktop/src-tauri/src/new_account.rs` exactly (delete only a young, device-less, single-Google-identity account; else keep) and show "No Warden account for <email>".
- Standalone network (same as desktop, see `DATA.md`): `register_device` (platform from `runtime.getPlatformInfo().os`: mac→macos, win→windows, linux→linux, android→android; name e.g. "Firefox on Android"; install id random, kept in storage), `heartbeat` every 60 s, `block_targets` read every 60 s, `spend-tick {device_id, site, seconds, evidence}` every 30–60 s of drain and on site change and at 0, local countdown from the balance token (alarm at the moment points reach 0), refresh token before expiry (single-flight). Session in `storage.local` (no OS keychain in an extension; say so in DATA). Timing from stored timestamps, not timers (MV3 background stops when idle).

## Desktop builder (`desktop/`)
- Native host = the same binary started by the browser. Early in `main.rs`: if the launch args look like a browser host launch (Chrome: an arg starting `chrome-extension://`; Firefox: args are the host manifest path + the Firefox extension id), run `native_host::run()` and exit; no Tauri. It relays stdio frames ↔ the running app over a local socket (macOS: Unix socket in the app data dir; Windows: named pipe per user, e.g. `\\.\pipe\warden-staging-ext-<user SID or name>`). If the app is not running, start it (macOS `open -b <bundle id>`, Windows the exe beside it) and retry a few seconds; keep retrying every 5 s. Tell the app which browser it serves: walk parent processes to the first known browser (`platform::KNOWN_BROWSERS`; Windows Chrome starts hosts through `cmd.exe`) and send its app id in the socket handshake.
- The app registers the host at every start (idempotent, per user, no admin): writes the host manifest JSON (path = this exe, `allowed_origins` = Chrome id / `allowed_extensions` = Firefox id) to: macOS `~/Library/Application Support/{Google/Chrome, Google/Chrome Beta, Chromium, Microsoft Edge, BraveSoftware/Brave-Browser, Arc/User Data, Vivaldi}/NativeMessagingHosts/` and `~/Library/Application Support/Mozilla/NativeMessagingHosts/` (also Chrome for Testing for tests); Windows: JSON in app data + HKCU `Software\{Google\Chrome, Microsoft\Edge, BraveSoftware\Brave-Browser, Chromium, Vivaldi, Mozilla}\NativeMessagingHosts\<host>` default value = JSON path. Check the current Chrome + MDN native messaging docs for exact paths.
- Drain: a known browser in front WITH a connected extension for that browser → no whole-browser drain; drain only when its last `tab.site` is guarded and not idle, tick `spend-tick {site: host}` (not target_id). Browser without extension → whole-browser drain as today. Locked + browser with extension on a guarded site → no full shield over the browser; send `state.locked` (the extension shows the blocked page). Pill label = the site ("youtube.com · 42 pts left"); pill Stop → `close_tab`. Popover browsers row shows which browsers have the extension. Send `state` to every connected extension on each change.
- Update root `DATA.md` (the site host now sent in spend-tick for browsers with the extension; nothing else) and `desktop/STATUS.md`.
- Windows NSIS installer for Jojo's Windows test: cross-build (`brew install nsis` if needed, `cargo xwin` runner per current Tauri docs). Output path in STATUS. Mac: rebuild the debug `.app`.
- Checks: those in `CLAUDE.md` (fmt, clippy, test, Windows check, tsc). Unit tests: site match, frame codec, host-launch arg detection, browser drain choice. Staging test: fake Mac with Chrome in front + fake extension reporting `m.youtube.com` (guarded `youtube.com`) → server charges with `site`; same with no extension → whole-browser tick. A real host round trip: run the built binary in host mode with framed stdin against the running app socket.
