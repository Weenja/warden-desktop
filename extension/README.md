# Warden browser extension

Guarded sites spend the points you earn in the Warden phone app, and lock when the balance reaches
zero. Supported browsers: Chrome and Chromium-based browsers (Edge, Brave, Arc, Vivaldi) and Firefox
(desktop and Android). Everything the extension sends is listed in [`DATA.md`](DATA.md).

The extension has two modes:

- **Linked**: the Warden desktop app is installed on this computer. The extension reports the front
  tab's site to the app over native messaging and shows the app's state. It makes no network calls
  of its own.
- **Standalone**: there is no desktop app (Firefox for Android, or a computer without the app). The
  extension signs in and talks to the Warden API itself.

## Build

```sh
cd extension
npm ci
npm run build   # Chrome and Firefox builds and zips in dist/
npm run check   # tsc --noEmit, unit tests, web-ext lint
```

Node.js 22.18 or later is required. `npm run build` also produces builds against the test backend,
used for internal testing. Icons are generated by `scripts/make-icons.sh` (ImageMagick); the PNGs
are committed.

The Chrome build carries a fixed public `key` in its manifest, which gives it a stable extension id.
The desktop app allows only that id to start its native messaging host. The private key is not in
this repository; it is needed only to pack a `.crx`.

## Install

### Chrome, Edge, Brave, Arc, Vivaldi

1. Unzip `warden-chrome-<version>.zip` into a folder you will keep.
2. Open `chrome://extensions` (Edge: `edge://extensions`) and enable **Developer mode**.
3. Choose **Load unpacked** and select that folder (from source: `extension/dist/chrome`).
4. Pin the Warden icon. With the desktop app running and signed in, the popup shows
   "Linked to Warden on …"; without it, the popup offers sign-in.

### Firefox (desktop)

Firefox permanently installs only add-ons signed by Mozilla. Until Warden is listed on
addons.mozilla.org, load it as a temporary add-on:

1. Open `about:debugging#/runtime/this-firefox` and choose **Load Temporary Add-on…**.
2. Select `warden-firefox-<version>.zip` (or `extension/dist/firefox/manifest.json`). It stays
   installed until Firefox quits. From source, `npx web-ext run -s dist/firefox` opens a fresh
   profile with the extension loaded.
3. If Firefox turned off access to the Warden API site at install, the first
   **Continue with Google** asks for it.

### Firefox for Android

Standalone mode only; Android has no native messaging. Requires Firefox for Android 142 or later.

- **Temporary install over USB**: install the Android platform tools (`adb`), enable USB debugging
  on the phone and, in Firefox, Settings → **Remote debugging via USB**. Then:
  ```sh
  npx web-ext run -t firefox-android -s dist/firefox --adb-device <id> --firefox-apk org.mozilla.firefox
  ```
  (`org.mozilla.firefox_beta` for Beta, `org.mozilla.fenix` for Nightly.) The extension stays until
  Firefox restarts.
- **Signed unlisted `.xpi`**: requires an addons.mozilla.org account and its API keys:
  ```sh
  npx web-ext sign -s dist/firefox --channel=unlisted --api-key "$AMO_JWT_ISSUER" --api-secret "$AMO_JWT_SECRET"
  ```
  Copy the `.xpi` to the phone. In Firefox: Settings → About Firefox → tap the logo five times,
  then Settings → **Install extension from file**.

## Native messaging protocol (linked mode)

The browser starts the desktop app's helper `warden-native-host` when the extension calls
`runtime.connectNative(<host>)`; the helper relays messages to the running app. Messages are JSON,
framed by the browser with a 4-byte length prefix. Types are defined in `src/protocol.ts`.

Extension → app:

- `{"type":"hello","ext_version":"0.1.0"}` on connect.
- `{"type":"tab","site":"m.youtube.com"|null,"idle":false}` on every change. `site` is the
  lowercase host of the active tab in the last focused window (`null` for non-web pages); `idle`
  means the screen is locked, or there was no input for 5 minutes while the tab plays no audio.
- `{"type":"show_app"}` when the user presses "Open Warden".

App → extension:

- `{"type":"hello","app_version":"…"}`.
- `{"type":"state","signed_in":true,"points":42,"low":false,"locked":false,"guarded_sites":["youtube.com"],"draining":{"site":"youtube.com","per_min":1}|null,"device_name":"…"}`
  after hello and on every change. `locked` means guarded sites are blocked: zero points, an
  expired offline balance, or today's maximum spent.
- `{"type":"close_tab","site":"youtube.com"}`: the pill's Stop button, or a lock while a guarded
  site is open.

If `connectNative` succeeds and the host answers `hello`, the extension is linked; "host not found"
means standalone. It checks again at browser start and every 5 minutes while standalone. A host is
guarded when it equals a guarded site or ends with "." followed by it (`m.youtube.com` is under
`youtube.com`). The server decides the charge.

The app accepts connections only from its own helper, started by a browser, and the browser lets
only the allowed extension ids start the helper.

## Known limitations

- Firefox for Android: if the server enforces Android attestation, a standalone extension gets
  `401 attestation_failed` on heartbeat and spend-tick.
- The battery indicator needs today's maximum. Standalone mode has it; linked mode shows it only
  when the app includes `daily_max` in `state`.
- The toolbar badge at zero shows "0" on a coral background; badges are text only.
